# Learning guide

1. **Embeddings are learned representations.** MiniLM was pretrained/fine-tuned by its authors. This project performs inference, not training. The 384 numbers encode a sentence/paragraph so similar meanings often point in similar directions, even with different words. A vector is not a summary, a fact checker, or a lossless representation of the text.
2. **Cosine similarity.** `cos(q,d) = (q·d)/(||q|| ||d||)`. With unit-normalized vectors it is just a dot product. It ranges approximately −1 to 1 and is not a probability. Read `Embedder.encode` and the best-chunk loop in `Organizer.search`.
3. **Chunking.** Long documents mix topics and exceed token limits. Here chunks are 160 words with 32-word overlap; adjacent chunks share context. The model truncates after its wordpiece limit, so word-count chunking is an approximation. Try inspecting a technical identifier-heavy chunk before assuming all its words were embedded.
4. **Ranking.** Semantic mode uses the most relevant chunk for each document. This supports local evidence but can favor long documents with more opportunities to match. Keyword mode uses substring/term coverage. Hybrid mixes the two at 0.7/0.3; these weights were chosen for simplicity, not optimized. Neither score says a result is objectively relevant.
5. **Caches and persistence.** Trace a chunk hash into SQLite. Identical text under the same model revision reuses a vector. Switching model versions requires new keys/indexing. Metadata edits affect lexical retrieval without pretending to regenerate the original document contents.
6. **Explainable metadata.** Inspect category term lists and the evidence display. Strength combines how many rule terms matched and how far the winner is ahead; it is not calibrated accuracy. Extractive summaries quote existing sentences, which can still omit important context. User edits are authoritative metadata and leave original suggestions intact.
7. **Evaluate honestly.** Read every query and rank in `results/evaluation.json`. Calculate Recall@1 and reciprocal rank yourself. Eight simple synthetic queries are a demonstration, not a realistic benchmark. Expand to diverse, human-labeled documents and held-out queries before claiming general accuracy.
8. **Safe software matters.** Explain why a filename is not a storage path, why SQL parameters matter, why textContent avoids active markup, why parser subprocesses help, and why they are not a full sandbox. Trash is reversible organization, not secure deletion. Embeddings and summaries can reveal sensitive information even if originals are hidden.

Suggested changes after understanding the project: add a new explainable category with tests, add a held-out paraphrase query without changing ranking weights, or add a cache-hit diagnostic. Avoid starting with an LLM/API wrapper. Be clear about AI assistance and which pretrained work belongs to the model authors.
